## Architecture

- **Stack**: NestJS + TypeORM + PostgreSQL, CQRS, AutoMapper, RabbitMQ
- **Auth**: Clerk JWT → `ClerkJwtStrategy` → looks up `branches WHERE user_id = dbUser.id` → sets `AuthenticatedUser.branchId` + `locationIds`
- **Access**: `hasOrgWideAccess = !managedBranch` — users with no branch get org-wide access
- **Roles**: `super_admin`, `org_admin`, `branch_manager`, `driver`, `packer`
- **Layer rule**: Application layer = interfaces/commands/queries/domain; Infrastructure layer = TypeORM implementations

## Key Domain Flows

### Purchase Order
Create (draft) → Receive (`status = received`) → Allocate (`status = partially_allocated | allocated`)

### Bill / Sale
`INITIATED → DRAFT → COMPLETED | CANCELLED`
Sale types: `normal / credit / black`
Payment timing: `cod / before_delivery / after_delivery / half`
Customer types: `regular / new / shop / big_customer`
Payment methods: `CASH / CARD / UPI / NET_BANKING / CHEQUE / CREDIT`

### Black Sale
Requires unpublished stock → `POST /unpublished-stock/add` → complete bill → optionally publish via `POST /unpublished-stock/publish`

### Stock Transfer (direct)
`POST /stock-transfers` (header) → `PUT /stock-transfers/:id/complete` (with items)
Each item: `{ fromInventoryId, toInventoryId?, productId, fromLocationId, toLocationId, quantity }`
`toInventoryId` is optional — backend auto-creates destination inventory if missing

### Stock Transfer Request (branch-to-branch)
`POST /stock-transfer-requests` (raise) → `PUT /:id/accept` (accepting location deducts) → `PUT /:id/claim` (requesting location receives)
Claim auto-creates inventory at requesting location if first time holding product

## Architectural Rule Enforced This Session

> **"All the operations should be directly in the repo — never inject DataSource in the handler."**

First attempt at the claim handler fix injected `DataSource` directly in the constructor. Rejected by the user. Correct pattern: add an optional `manager?: EntityManager` parameter to the repo method; when the caller has an existing transaction it passes the manager; when it does not, the repo opens its own via `this.internalRepo.manager.transaction(run)`.
